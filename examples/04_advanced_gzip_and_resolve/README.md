# 4. Advanced: gzip-compressed includes and resolving to a file

Combines several features:

- `base_config.yaml` has chained `!ref`s (`fallback` refs `primary`,
  which `service.region` also refs). Note the paths are written as
  `base.regions.primary`, not `regions.primary` — `!ref` always
  resolves against the final top-level document, and `config.yaml`
  includes this file under the `base` key. A ref inside an included
  file cannot assume it's resolving against its own file's root.
- `config.yaml` `!include`s a gzip-compressed dataset
  (`large_dataset.yaml.gz`, generated by the script) alongside a
  plain file.
- `resolve_to_file()` writes the fully-resolved config back out as a
  gzip-compressed file, which is then reloaded to show it round-trips.

```bash
uv run python examples/04_advanced_gzip_and_resolve/run.py
```

`large_dataset.yaml.gz` and `resolved.yaml.gz` are generated by the
script and not committed to the repo (see `.gitignore`).

This is the intended "compile once, ship the resolved file" pattern:
resolve a config with includes/refs/defaults into a flat file once
(in CI, at build time, ...), then have the runtime `load()` the
resolved file with no ycon tags left to process.
